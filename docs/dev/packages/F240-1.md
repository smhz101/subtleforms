# Package F240-1: Server validation parity

Repository: `subtleforms`. Release: Free 2.4.0. Branch from `release/2.4.0` as `pkg/F240-1`. Owner: Claude.

Standing rules: .cursor/rules/subtleforms.mdc. Bugs below are the whole task; each one needs a regression test.

## Instructions
One place in FieldValidator for per-type value checks: option membership, booleans, dates and times (ISO), ranges, steps, matrix rows and columns, colour hex, signature data URI, read-only, arrays for scalar fields, phone E.164 with country, payment field limits. Messages match the browser and are translatable. Table-driven WP test: one bad and one good value per field type.

## Bugs (19)

### FA-01 (P2) Still open
- Repro: REST POST /subtleforms/v1/submit to a form with date (min/max, read-only), time, datetime, rating (7), NPS, slider (10 to 50 step 5), matrix, signature, colour with: d1 "not-a-date", d2 changed, t1 "99:99", dt1 "garbage", r1 99, n1 15, sl1 7, m1 {"Speed":"Nope"}, sig "hello", col "javascript:alert(1)"
- Expected: 422 with field errors
- Actual: 200, entry 680 completed with every value as posted, also in email, CSV and PDF
- Likely cause: src/Engine/FieldValidator.php:233-286, the type switch has no case for these types; validateDateBounds (461) skips non ISO values; readOnly is never checked
- Report: docs/dev/qa/2.3.3/fields-advanced.md
