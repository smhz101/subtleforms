# Package F240-6: Payments, free side

Repository: `subtleforms`. Release: Free 2.4.0. Branch from `release/2.4.0` as `pkg/F240-6`. Owner: Claude.

Standing rules: .cursor/rules/subtleforms.mdc. Bugs below are the whole task; each one needs a regression test.

## Instructions
Work through each ID. Currency list and zero-decimal rounding through one Currencies helper; payment data kept through Tools export and import.

## Bugs (14)

### PAY-09 (P2) Still open
- Repro: Form currency JPY (or site EUR) with a Custom Amount field.
- Expected: Symbol "¥"
- Actual: "$" shown next to the amount input while the summary shows ¥
- Likely cause: Field default `currency => 'USD'` (CoreFields.php ~1572) is saved into the field and preferred by FieldRenderer.jsx:889 over the form currency; no control to change it
- Report: docs/dev/qa/2.3.3/payments.md

### PAY2-01 (P2) new in 2.3.8
- Repro: Tools > export submissions of a payment form, then import the file (same or another form). Also export an entry with status payment_failed
- Expected: Entries keep the order (lines, coupon, total), payment status, gateway and transaction ID; "submission state is kept" (changelog 2.3.6)
- Actual: Imported entries 5962, 5963 have no order and no payment meta, so no Order panel, no PDF order summary, no "View in Stripe". payment_failed entry 5945 imported as 5964 with status "unread"
- Likely cause: src/Tools/TransferService.php exportSubmissions rows carry only status, is_read, starred, created_at, payload; importSubmissions creates without meta. TransferPackage::status() allowed list (TransferPackage.php:214) lacks payment_failed (and other pipeline statuses)
- Report: docs/dev/qa/2.3.8/payments.md

### PAY2-02 (P2) new in 2.3.8
- Repro: Site currency EUR (Settings > Integrations > Payments). Open a priced form, Settings > Payments, change anything and Update
- Expected: Form follows the site currency unless the admin picks one
- Actual: Stored metadata.payment becomes {"currency":"USD","processor":"subtleforms"}; quote for that form is USD while a form never saved there is EUR. The Payments tab offers no currency control for the SubtleForms processor, so it cannot be fixed in the UI
- Likely cause: src/Validation/Schemas.php:494 `'currency' => 'optional
- Report: docs/dev/qa/2.3.8/payments.md

### PAY-12 (P3) Still open
- Repro: JPY form, product 1250.50, tip 100.70.
- Expected: Prices rounded to whole yen everywhere, or decimals refused
- Actual: Display ¥1,251 and ¥1,351; Stripe 1351; entry stores 1351.2
- Likely cause: Pricing::money() always rounds to 2 decimals; only toMinor() knows zero-decimal currencies
- Report: docs/dev/qa/2.3.3/payments.md
