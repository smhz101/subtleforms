# Package F239-5: Field and pricing P1s

Repository: `subtleforms`. Release: Free 2.3.9. Branch from `release/2.3.9` as `pkg/F239-5`. Owner: Claude.

Standing rules: .cursor/rules/subtleforms.mdc. Bugs below are the whole task; each one needs a regression test.

## Instructions
Name and Address part settings saved as a keyed map and honoured everywhere (FB-01, FB-02, FB-10, FB-12, FB-17). Notice, Section Heading and Page Break inspector controls and step description shown (FA-02, FA-21). Repeater row uploads moved out of pending and linked (FA-03). Dependent dropdown values derived from labels with unique, never-reused IDs, Columns layout does not pre-submit, required chains need every level (FLD2-02, FLD2-03, FLD2-09, FLD2-10). Pricing decides visibility from conditional logic, never from key presence; hidden Fixed Fee not charged and not printed (PAY-01, PAY-02, PAY-18).

## Bugs (15)

### FA-02 (P1) Still open
- Repro: Builder: add Notice, Section Heading or Page Break from the library and open Settings
- Expected: Text/style, title fields
- Actual: Notice shows only CSS class and "Layout field: configure via canvas"; Section Heading and Page Break show only Description. A new Notice is empty and is hidden on the live form; step titles stay "Step 1"
- Likely cause: layoutControls of these types have no `section`; DynamicInspectorPanel.jsx:134 files them under "appearance", but FieldInspector.jsx:370 (AppearancePanel) only renders when the definition itself declares an appearance control, so the panel is never shown. FieldSettings.php only tags layoutControls for containers
- Report: docs/dev/qa/2.3.3/fields-advanced.md

### FA-03 (P1) Still open
- Repro: Repeater with a File Upload child; upload small.txt in row 1 and submit
- Expected: File stored with the entry, download link
- Actual: Record stored but the file stays in uploads/subtleforms-uploads/pending (removed by the daily clean-up); entry shows the raw JSON record, email and CSV show "id, name, size, type"; a forged record {"id": other entry's file, "name":"forged.pdf"} inside a row is accepted and stored (entry 807)
- Likely cause: Uploads::resolvePayload (src/Uploads/Uploads.php:366) and recordsIn (461) only look at top-level keys
- Report: docs/dev/qa/2.3.3/fields-advanced.md
